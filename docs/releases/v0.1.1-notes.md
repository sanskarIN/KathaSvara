# KathaSvara v0.1.1 — Developer Preview (Source Only)

**Pre-release:** v0.1.1 is an experimental, source-only preview for developers of Hindi storytelling and offline-first text-to-speech workflows. It is **not** a complete packaged application and does **not** include model weights, a Windows installer, or any generated speech recordings.

## Changes since v0.1.0

- **Local TTS setup diagnostics:** Settings → **Inspect local TTS setup** checks whether `numpy`, `soundfile`, `torch` and `chatterbox` are discoverable in the configured Python runtime, and reports Python version and platform.
- **New Python protocol:** `{"action":"diagnose"}` returns the local dependency readiness report without loading, downloading or initializing model weights.
- **Honest readiness reporting:** Setup diagnostics explicitly mark `model_weights_verified=false` and `audio_synthesis_verified=false`, even when all optional packages appear installed. An installed library is not proof of playable Hindi audio.
- **New automated tests:** Added deterministic dependency-present/absent tests, diagnostic protocol tests, and the already-existing CLI inspection, speech chunking, WAV transport, web app and Rust native checks.
- **Version consistency:** Updated Python inference, React frontend and Rust/Tauri application versions to `0.1.1`.
- **Documentation:** Development-mode setup instructions and engineering notes for the diagnostic pathway.

## What is still experimental

- The Hindi speech adapter uses upstream **Chatterbox Multilingual TTS**. Genuine end-to-end Hindi narration quality, pronunciation, model selection, GPU compatibility and voice consistency **have not been verified by listening**.
- The application must be launched from source with Python and Tauri development prerequisites. **No tested installer, executable, bundled sidecar, or checksums for binaries are provided.**
- A one-shot Python worker is used for each generation request. There is no managed long-running inference service, full cancellation UI, or long-story batch production pipeline yet.
- Local generation is limited to 3,000 Unicode code points per request. The existing UI supports a single narrator pathway, WAV preview/export and local story files; it is not a multi-character production studio.
- External Chatterbox code, checkpoints and dependency licenses are separate from the **MPL-2.0** KathaSvara application code.

## Getting started

1. Download the automatic GitHub **Source code (zip)** or **Source code (tar.gz)** attachment, or clone the repository and check out tag `v0.1.1`.
2. Follow [development setup](../installation/development.md) for Python 3.11, Node.js, Rust and Tauri requirements.
3. In the `services/inference` directory, create a virtual environment and install `python -m pip install -e ".[tts,test]"`. Model downloads may require network access, substantial disk storage and compatible hardware.
4. Configure `KATHASVARA_PYTHON`, then from `apps/desktop` run `npm install` and `npm run tauri dev`.
5. Open **Settings → Inspect local TTS setup**. Dependency presence does **not** validate weights or actual Hindi audio.
6. Only if the runtime supports it, generate your own short Hindi test and listen carefully before relying on it.

For a lightweight, no-download diagnostic, with the Python environment active:

```sh
cd services/inference
echo '{"action":"diagnose"}' | python -m kathasvara.cli
```

## Automated and manual verification

The GitHub pre-release publishing job requires **Python Ruff + pytest**, **React tests + TypeScript/Vite build**, and **Windows Rust unit tests + Clippy** to succeed on the release commit. This validates development source, not installer deployment, model compatibility, or audible narration quality. See [release checklist](v0.1.1.md) and [tracking issue #1](https://github.com/sanskarIN/KathaSvara/issues/1).
