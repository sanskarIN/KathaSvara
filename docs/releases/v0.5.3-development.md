## Core audio-generation reality check and Windows recovery path

The audio generator is intended to produce **real Hindi narrated WAV files** from Chatterbox Multilingual, not merely manage stories or simulate audio. The experimental GitHub executable is **not** self-contained: it does not bundle Python 3.11, Chatterbox, PyTorch or weights, and a source checkout is needed at runtime. Prior CI passed no-model tests but never established end-to-end synthesis or clean-machine launch. This remains an open blocker for any stable release.

The [Windows audio troubleshooting guide](../installation/audio-troubleshooting.md) now documents an opt-in local helper `scripts/windows/launch-with-audio.ps1`. **DoctorOnly** verifies the selected Python 3.11 bridge/dependencies without installing or loading a model; **InstallDependencies** explicitly installs external Python packages in a local venv; **VerifyHindiSpeech** explicitly runs real Chatterbox synthesis to a unique temporary WAV for human listening, possibly downloading model weights. The helper launches a trusted, checksum-verified developer EXE with the inference directory and Python interpreter set only for the child process. It does not modify registry, install an unsigned EXE, accept model terms, or claim synthesized audio was verified. Windows CI now syntax-checks this script with no downloads.

Voice Studio also previously **deleted an otherwise completed WAV** if it exceeded the 25 MiB base64 inline-preview cap. Large, structurally validated PCM WAVs are now retained with `preview_available: false`, a clear export-only message and a visible **Export WAV** control. Small WAVs still receive a validated inline playback data URL. Windows Rust unit tests exercise both paths, while the existing scene renderer's export-only behavior remains unchanged.

These changes improve actual failure recovery and make generation requirements testable, but **real Hindi sound, first-run model download, packaging and clean Windows installation remain unverified** in automated CI. Do not release as a stable audio generator until the manual acceptance issue is completed.


## Cooperative cancellation and independent recovery deletion

The **Cancel render** control now accepts at most one cancellation IPC signal for each active narration job. While the signal is in flight it displays **Requesting cancellation…** and stays disabled; after acknowledgment it displays **Cancellation requested (waiting)** until the current job finishes. This is a request, **not** proof that inference or the current model chunk has stopped. If the signal fails, it returns to **Cancel render** and reports the failure so the user can retry. Story switches, source edits, new renders and completed renders retire stale cancellation ownership; late responses cannot mark the wrong job as cancelled. The renderer's existing generation/cached-audio safeguards remain in place.

Concurrent deletion of local render recovery journal records is now supported: each **Forget record** action is owned by a distinct job ID and request token. Forgetting record B no longer invalidates record A's eventual deletion result, even if completions arrive out of order. Duplicate forget clicks on the same pending row are ignored, and the row shows **Forgetting record…**. An IPC failure leaves the record and allows an explicit retry. Confirmed deletions are excluded from later stale history reads during the same document session, while switching documents retires old deletion UI ownership. The operation does not remove source projects, generated WAV files, exports, or speech caches.

Model-free React/Tauri tests cover rapid cancellation clicks and acknowledgments, cancellation IPC failure and retry, two history deletions resolving in reverse order, stale read filtering, duplicate clicks, retryable deletion failure, and unchanged source/voice data. Human Hindi listening, clean-Windows launch and reliable cancellation latency still require hands-on acceptance.


## Generation-start ownership for local plans, audits and export dialogs

Starting an actual local narration attempt now retires all pending, model-free **render-plan** and **production-readiness audit** requests before dispatching synthesis. Their independent epochs advance, their busy indicators clear, and the previous audit and plan are removed. A late audit or plan response cannot be misrepresented as proof that the active generation passed preflight or is acoustically correct.

If the creator had opened the export destination dialog for a privacy-safe audit JSON and starts narration before choosing a path, that export is abandoned: the dialog's original audit epoch must still be current when it resolves and when the filesystem export completes. This prevents exporting obsolete counts for a different generation state or showing a misleading success message. The guard also checks editor-busy and active-render ownership. Starting a render while a parse/save operation is active is refused at the handler, not only by its button.

Mocked Tauri/React tests exercise simultaneous pending plan and audit requests, synthesis starting during both, delayed completion, and destination selection after a render begins. They verify no stale status, no stale manifest IPC, no source edit, and uninterrupted current preview. These tests perform no model inference or actual narration QA.


## Concurrent editor operations and render recovery

Model-free **render-plan inspection** and **production-readiness audits** now have separate request-epoch ownership. Switching stories or editing the current document retires previous requests immediately, releases their busy indicators for the new story and prevents a delayed completion/error/finally handler from showing a stale report or unlocking a newer request. The no-model inspection itself remains non-destructive and should not be read as confirmation of acoustic quality.

**Save cast and scenes** is disabled while narration is running, and the handler also checks the active render job before saving. Saving returns a new parent StoryV2 object; this gate prevents a seemingly harmless save from silently retiring an in-flight render via the document-change effect. The save action becomes available again after the render settles. Cancellation messages are also scoped to the job: a delayed cancellation acknowledgment or error must not be attributed to already-completed audio or a later render.

Mocked React/Tauri tests exercise overlapping plan responses, overlapping audit responses, story replacement, unchanged original dialogue, safe saving during narration and cancellation acknowledgment after a job finishes. These are deterministic no-model tests, not real Hindi narration listening, production audio verification, or a clean Windows installation test.


## Validate character/scene creation before retiring audio

The **Add character**, **Duplicate voice profile**, and **Add scene** controls now validate and materialize their proposed changes synchronously before calling the shared editor mutation routine. A duplicate name, invalid scene title, ambiguous duplicate-profile source, or other rejected input is reported immediately without dispatching an invalid React state updater, marking the document edited, discarding an existing WAV preview, or interrupting narration. Successful duplication creates its new ID and clone only once rather than generating identities inside a React state updater that may run more than once.

New mocked React/Tauri tests confirm duplicate character names preserve a previously generated preview and make no discard IPC call, malformed duplicate-character IDs are reported without onChange, overlong scene titles do not mutate the document, and successful scene/profile creation preserves original source text with stable cloned IDs. These tests do not load a speech model, confirm separate voices, or establish real Windows installation and listening quality.


## Fail-closed scene and character render preflight

Render selection now rejects **non-null speaker IDs that are absent from the current cast**, as well as speaker IDs occurring more than once in the character library. Both manual model-free plan inspection and actual generation use the same validation before native IPC. Stage directions do not create speech assignments and are not mistaken for voice turns.

A selected scene or line must also have an unambiguous identifier. The selection helper rejects duplicate scene IDs within the chosen rendering scope, duplicate line IDs across selected spoken lines **or directions**, and line-scoped requests where the line ID appears more than once anywhere in the story. A malformed unrelated scene need not prevent inspecting/generating a separately valid scene, but a named line can never select several ambiguous records. This keeps source selection deterministic and guards against accidentally re-rendering the wrong dialogue.

For non-null invalid speaker assignments, the line's **Regenerate / retry this line only** control remains visible but disabled with a repair instruction. The speaker selector remains available for manual correction. Source-only TypeScript tests and mocked React/Tauri tests cover missing/deleted speaker IDs, duplicate character IDs, duplicate scene/line IDs, direction-only metadata, separate valid scenes and the absence of model or preflight IPC on invalid requests. No automatic repairs, original Hindi edits, cloud calls, or generated-audio quality claims are involved.


## Safe reviewed-text editing during generation

The **Reviewed spoken text** field is now disabled while parsing, saving, or generating narration, consistent with the other source-edit controls. A delayed blur event is rejected while the editor is busy or rendering and its visible value reset to the currently saved reviewed text. This prevents a stale textarea edit from silently retiring a running speech job or replacing the source snapshot it captured. The text remains editable after the operation returns to idle. A mocked desktop integration regression checks the disabled field, rejected late blur, preserved Hindi text, uninterrupted render, and re-enabled field after a completed mocked WAV.

This guard neither establishes successful synthesis nor supplies automatic review; actual Hindi listening and clean-Windows acceptance remain manual checks.

## Manual speaker-review navigation

### Jump directly to a dialogue issue

Long stories can now use the **Jump to speaker issue** selector alongside Previous / Next. Each local option has the issue number, a short whitespace-normalized Hindi scene title, whether the speaker is unassigned or references a missing character, and a bounded excerpt of the original dialogue. Selecting an option exposes the destination even if a scene-search or character filter had hidden it, selects the scene, highlights the line, and focuses its speaker selector. The live status gives the current issue position and reason; once the line has been fixed, the picker reverts to its placeholder rather than falsely claiming it remains unresolved. The jump picker and both navigation buttons are disabled when no issues remain.

Options are computed entirely from source metadata already present in memory. The dropdown does not synthesize speech, auto-assign any character, persist changes or send dialogue to a service. Both source-level and mocked React/Tauri tests cover Hindi excerpts, bounded labels, mixed missing/unassigned assignments, direct focus, clearing hidden filters, issue progress, complete repair and unchanged source data.


**Reverse review:** The companion **Previous speaker issue** button moves backwards through the same local-only source-order queue and wraps from the first issue to the last. Like forward navigation, it can continue relative to a just-corrected line, clears filters that would hide the destination, focuses the affected speaker selector, and does not update project content. With no outstanding spoken-line issues, both navigation buttons are disabled. Regression tests cover mixed unassigned/invalid speakers across scenes, backward wrap, corrected targets, empty queues, and the absence of model IPC.


The **Next speaker issue** button moves through the active v2 document's spoken lines in source order, visiting both unassigned speech and speech pointing at missing characters. It selects the affected scene, highlights its original line, and focuses that line's speaker selector for an explicit manual correction. At the last issue, it wraps around to the first; if a previously visited line was corrected, the next click continues forward from that still-existing line instead of starting from the beginning.

Navigation clears scene search, cast, and review filters when needed so an issue cannot be hidden by a previous query. Switching stories resets the navigation cursor; manually picking a different scene also clears the current highlight. The button is disabled when no speaker issue exists or when the editor is parsing, saving or rendering. Silent stage directions are ignored even if their stored speaker field is malformed.

The issue queue is calculated in memory, sends no data to the speech model, and does not modify or save the original Hindi source, review text, speaker assignments or audio. Model-free unit tests cover review order, wraparound, fixed-line navigation and empty queues. Mocked desktop tests cover control focus, hidden filters, repair continuation and story switching. This feature is not automatic voice identification and is not an audio acceptance result.


## Repair missing character references from the scene outline

The **Only scenes needing speaker review** filter now includes both speech with no assigned character and speech whose non-null character ID no longer appears in the current cast. Counts remain separate: each scene shows `unassigned` and `invalid speaker ID(s)` independently, and the local cast report continues to distinguish the two failure classes. A scene with malformed speaker references can therefore no longer disappear from the review navigator just because the reference is not `null`.

The desktop displays a prominent warning when spoken segments reference absent character IDs, and the affected segment's speaker selector explicitly shows a disabled **Invalid character ID — choose a valid speaker** option until the creator chooses a valid character. Unspoken stage directions are excluded from all missing-speaker counts and review filters, even if they contain stale speaker metadata. Search and cast filters can still be combined; fixes are reflected immediately on the next document update. This is local, source-only feedback: it neither repairs characters automatically nor generates speech, changes original Hindi dialogue, transmits story content, or certifies audio quality.

Pure TypeScript tests and a mocked Tauri/React regression check unknown-ID navigation, valid speaker repairs, disabled bad-ID selection, unchanged source text and ignored invalid IDs on stage directions. Existing human Hindi and clean-Windows manual acceptance remain outstanding.


## Creator-facing cast coverage (source-only)

The Character and Scene Studio now contains an expandable **Local cast coverage** summary that counts actual spoken turns and how many distinct scenes contain each character. It also counts stage directions, unassigned speech, and non-null speaker references that do not match any known cast member. Invalid references are reported separately so a malformed project is not falsely described as fully cast. Stage directions do not add speaker appearances, regardless of their stored speaker field. The counts always cover the complete current document, regardless of scene search or navigation filters.

This summary is computed locally from the current v2 story, uses a bounded scrollable list for a large cast, makes no calls to the voice model or filesystem, and does not edit original text, user notes, audio metadata, or speaker IDs. Two pure TypeScript regression tests and one mocked React/Tauri test cover speaker counting, distinct scene counts, invalid IDs, collapsed navigation, and no IPC or editor mutation. Neither counts nor saved voice parameters verify distinct voice identities or actual listening quality.

## Isolated rendering sessions across story changes

An in-progress narration is now associated with a single active render job. Switching to another story, or making a document edit, retires the previous job, requests cooperative cancellation, resets the old progress controls, and permits a fresh attempt for the active story. The old worker can still finish after cancellation; its late audio result is discarded and its response, error, or `finally` cleanup cannot stop the new job or overwrite the new story's progress and preview. Polling results are also scoped to the currently owned job. Two mocked Tauri/React race regressions cover late successful audio and late failed synthesis arriving after the next story's render has begun.

This is a desktop lifecycle fix, **not** guaranteed immediate termination of the native worker, safe recovery of interrupted content, successful Hindi synthesis, or proof of end-user Windows readiness. An actively running model chunk may continue until cancellation can be processed. No audio/model dependencies or release manifests change.

## Cast-focused scene navigation (model-free)

The local scene outline now includes a **Show scenes for character** selector alongside text search and the unassigned-speech review filter. Choosing a character shows only scenes containing at least one **spoken** segment assigned to that character's stable ID; stage directions never count as character turns, even if malformed data contains a speaker ID. Search and unassigned-scene filters can be combined without changing scene IDs, line order, voice profiles, original Hindi source, stored notes, render output, or save state. Switching stories or removing the selected character restores the full scene outline. **All characters** and **Clear scene filters** return to normal navigation.

Unit and mocked React/Tauri regression tests exercise narrator/character filtering, unspoken directions, Hindi search composition, unresolved-review composition, deletion of a filtered character, and switching documents. These are model-free UI/source assertions, not tested Hindi listening, persistent on-device save, or Windows installation acceptance.

## Local searchable scene outline and unresolved-speaker navigation

To make larger Hindi story projects easier to review, the **Character and Scene Studio** now shows a searchable scene outline. Search finds partial matches in scene titles, nonspoken production notes, original dialogue, reviewed spoken text, stage directions, or unknown source-speaker labels. The query is trimmed, Unicode-NFC-normalized and case-insensitive for Latin-script words; no cloud index, external API or audio/model request is made. Filtering only changes which scene navigation buttons are shown; it never changes the source script, save state, synth cache or open scene until the creator explicitly selects a match. A no-results message offers a clear-filter action.

Each scene navigation entry shows its number of spoken lines, unspoken stage directions, unresolved speaker assignments and whether editorial notes exist. **Only scenes with unassigned speech** filters out scenes without unresolved spoken lines (directions with no speaker do not count). Statistics recompute on document changes, so assigning a speaker immediately updates the outline. Search and filters are cleared when the story ID changes, preventing private search context from hiding the next story's scenes. The user can still review/edit the currently open scene when it is filtered out of the navigation; a helper message makes that behavior explicit. Model-free TypeScript and mocked desktop integration tests cover this feature.

## New creator feature: reorder individual lines inside a scene

The Character and Scene Studio now provides **↑ Line up** and **↓ Line down** controls alongside each dialogue or unspoken stage-direction segment in the selected scene.

- Reordering only swaps neighboring lines in the current scene; it does not move an entire scene or change a script's original `text` field.
- Each segment keeps its original ID, speaker/actor assignment, original and reviewed Hindi text, source label, status, and per-line metadata.
- Buttons are disabled at the first/last line and when the editor is busy or the speech model is rendering; an edge move is a no-op.
- Missing or duplicated line identifiers fail closed rather than silently editing the wrong line.
- A real reorder uses the existing editor mutation function: it marks the document unsaved, invalidates stale render/review state, and safely discards an old current WAV. A separate Save action is still required to persist reordered scenes.
- No network calls, voice weights, new models or analytics are introduced. The ordering of speech segments is validated by the existing model-free production preflight at the next render.

## Splitting long Hindi scenes without rewriting narration

The scene editor now offers **Split scene here** next to each line after the first in the current scene. The operation inserts a new scene immediately after the original, moving that line and everything following it into the new scene. The original script and pronunciation glossary remain unchanged. All existing dialogue, staging, reviewed text, speaker IDs, segment IDs, and per-line generated audio references remain attached to their segments in their original overall sequence. This is a change to scene grouping rather than a duplicate or a new speech synthesis job; the editor still invalidates its current combined WAV preview and requires the user to Save before persistence.

The new scene receives a bounded, collision-resistant title based on the source scene title plus `(part 2)`, `(part 3)`, etc., and starts with blank editorial-only production notes. The original scene retains its notes. The editor disallows first-line splits (which would create an empty scene), prevents scene splits during active jobs, and refuses a 201st scene, ambiguous existing scene/line identifiers or malformed generated IDs. The pure helper also checks source and line uniqueness independently of the UI. Tested in no-model TypeScript and mocked-Tauri React flows, not with genuine Hindi narration or a clean Windows machine.

## Joining adjacent scenes without losing reviewed narration

The selected scene has a **Merge with next scene (keep dialogue)** action (disabled for the last scene and during active parsing or rendering). A confirmation explains that this is a structural merge, not a rewrite of the Hindi source script. The first scene retains its own ID and title, while the successor scene's dialogue and stage directions append in their existing order. The successor title and optional editorial notes are retained in the first scene's **nonspoken production notes**, separated from its original notes with a visible label.

No segment IDs, reviewed Hindi speech, voice assignments, cache references or measured line durations are altered. The current combined preview becomes invalid after a genuine edit, but the original script and glossary remain intact; creators must Save to persist the merged grouping. To protect the native save contract, the operation refuses an invalid or ambiguous scene ID, duplicated line identifiers, more than 2,000 lines in the combined scene, or notes exceeding 4,000 characters (including the preserved successor title). Test coverage includes cancellation, metadata retention, bounded notes, native limits and a merge which does not invoke narration synthesis.

## Scene templates by safe duplication

Long scene names now truncate on complete Unicode code-point boundaries when generating bounded copied titles, avoiding malformed surrogate pairs in emoji/mixed-script scene titles. The original source scene title remains untouched; no scene is rendered or saved automatically.

Creators can use **Duplicate scene (fresh audio)** on the active scene. The copy is inserted immediately after the original and selected for editing. Its reviewed Hindi text, stage directions and assigned speakers are retained, but its scene and line IDs are regenerated; copied lines are explicitly reset to **pending**, with no old audio reference or duration. Existing work stays untouched. The title becomes `(copy)`, `(copy 2)`, etc. (bounded to 120 characters).

The operation refuses a missing scene, an ID collision, a project already at 200 scenes, or duplication that would push the full-story speech total above the current 256-cue render/SRT limit. It does not clone model output or certify duplicate speech: a new render and human listening review are required. The source script and glossary stay unchanged and nothing is written until the user saves.

## Reliable deferred editor events

The desktop now captures the chosen speaker, destination scene, character name, and voice-slider numeric values **before** scheduling the React document update. This prevents delayed updates from reading a reset control value and accidentally applying an empty or old selection. Manual assignment and cross-scene line moves are checked with deferred React state-updater tests. The editor does not automatically infer voices or regenerate synthesis because a select changed.

## Live unresolved-speaker feedback

The unknown-speaker alert now reads unresolved speech lines from the **current scene document**, rather than retaining a one-time parser warning after the author manually reassigns a character. Resolving the final unknown speaker clears the alert, and switching to another story cannot leave the previous story's unknown labels displayed. This is a UI state correction, not inferred speaker identification or automatic voice conditioning. A mocked desktop test confirms manual speaker assignment and the cleared warning.

## Production notes and safe scene removal

- The selected scene has an editable **Production notes for this scene (not spoken)** field. Notes may contain newlines, are limited to 4000 characters (the native project storage limit), and reject nonprinting control characters. They remain attached to the saved scene, separate from the original script and spoken text; they are not read aloud.
- **Delete scene (keep original script)** shows an explicit confirmation before removing that scene from the edited v2 project. It leaves the original source script, other scenes, pronunciation glossary and characters unchanged; the result is unsaved until the user chooses Save.
- After deletion, selection moves to the next scene where possible, then the preceding scene, or an empty state if none remain. Editing or deleting a scene invalidates stale preview/review state through the existing mutation handler.
- Missing or duplicated scene IDs fail closed. Tests exercise multiline Hindi notes, invalid values, cancellation and deletion without a speech model. The user should save a backup before making large narrative changes; there is no automatic undo of a saved deletion.

## Character cloning safety and native save compatibility

The **Duplicate voice profile** action now checks the native 100-character cap, requires unique and valid character IDs, rejects ambiguous duplicate source IDs, and generates unique copied names within the native 120-character title/name limit. Long Hindi character names are trimmed at Unicode code-point boundaries when adding a `copy` suffix. The desktop disables Add and Duplicate controls when already at capacity and during active rendering. Copying a profile carries voice parameter *settings*, not an experimentally verified distinct speaker identity. Model-free tests cover ID collisions, caps, Unicode names and disabled controls.

## Scene identity integrity

Cross-scene moves now reject nonunique destination scene IDs instead of silently inserting a dialogue line twice. In-scene reordering also rejects an ambiguous source scene ID before editing. Freshly duplicated scene/segment identifiers are checked for emptiness, length (maximum 80 characters), control characters and collisions before accepting the copy. These checks protect save and render compatibility with the Python v2 contract; they do not repair pre-existing corrupted documents.

## Offline native round-trip regression tests

Additional Python tests now build a two-scene Hindi narrative, mirror the desktop's merge output as an ordinary version-2 JSON document, round-trip it through the native `from_dict` / `to_dict` validation contract, and verify that its source script, merged nonspoken notes, speaker mapping, line-level cache identifiers, durations, and narration order survive unchanged. A model-free render preflight confirms that the merged document still contains two spoken segments, without creating audio. Separate tests reject malformed documents with overlong notes or more than 2,000 lines in one scene. This strengthens save-contract confidence but is not a human-audited Windows save/load session.

## Native-save contract for new IDs and scene line moves

New scene and character IDs are now rejected locally if empty, padded with whitespace, longer than 80 characters or containing control characters, even before a native save attempt. Moving a line to another scene also verifies the destination remains within the native 2,000-segment-per-scene ceiling; moving a line to its own scene is an identity-preserving no-op. These checks prevent knowingly creating a project the Python schema would reject. Tests verify rejection does not mutate the original dialogue, and the guard does not claim that a Windows end-to-end save has been performed.

## Corrupt-document and no-op edit safeguards

Additional model-free safeguards prevent older editor operations from silently editing multiple records if a loaded file contains duplicate scene, cast or dialogue IDs. Scene reorder/rename, character rename/deletion, speaker assignment and reviewed-speech correction now require one exact intended target. A move-to-current-scene or unchanged reviewed voice/text does not modify the document or clear the line's cached metadata. Moving a line to a different scene retains the same line object and appends it once. Invalid/missing identifiers fail with explicit errors rather than reporting a successful edit.

The React studio disables ↑/↓ scene reordering at the boundaries and locks character names, sliders, deletion, scene titles, speaker assignment and cross-scene moves during a pending script parse or narration render. New mocked IPC tests exercise disabled controls and boundary behavior, while TypeScript unit tests check duplicate-ID documents and no-op stability. Normal rendering/recovery behavior remains unchanged; there is still no tested clean Windows or genuine Hindi model acceptance.
