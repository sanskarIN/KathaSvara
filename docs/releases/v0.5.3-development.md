# KathaSvara v0.5.3 — Scene dialogue ordering development

**Status: draft, post-v0.5.2 source development; NOT published or merged into main.**

This work begins only after the v0.5.2 candidate was prepared and fully checked. **v0.5.2 remains the latest source-release candidate; v0.5.1 remains the last published GitHub prerelease until a genuine v0.5.2 publication succeeds.** The v0.5.3 branch is intentionally isolated so its features cannot slip into the v0.5.2 exact-SHA release workflow.

## New creator feature: reorder individual lines inside a scene

The Character and Scene Studio now provides **↑ Line up** and **↓ Line down** controls alongside each dialogue or unspoken stage-direction segment in the selected scene.

- Reordering only swaps neighboring lines in the current scene; it does not move an entire scene or change a script's original `text` field.
- Each segment keeps its original ID, speaker/actor assignment, original and reviewed Hindi text, source label, status, and per-line metadata.
- Buttons are disabled at the first/last line and when the editor is busy or the speech model is rendering; an edge move is a no-op.
- Missing or duplicated line identifiers fail closed rather than silently editing the wrong line.
- A real reorder uses the existing editor mutation function: it marks the document unsaved, invalidates stale render/review state, and safely discards an old current WAV. A separate Save action is still required to persist reordered scenes.
- No network calls, voice weights, new models or analytics are introduced. The ordering of speech segments is validated by the existing model-free production preflight at the next render.

## Splitting long Hindi scenes without rewriting narration

The scene editor now offers **Split scene here** next to each line after the first in the current scene. The operation inserts a new scene immediately after the original, moving that line and everything following it into the new scene. The original script and pronunciation glossary remain unchanged. All existing dialogue, staging, reviewed text, speaker IDs, segment IDs, and per-line generated audio references remain attached to their segments in their original overall sequence. This is a change to scene grouping rather than a duplicate or a new speech synthesis job; the editor still invalidates its current combined WAV preview and requires the user to Save before persistence.

The new scene receives a bounded, collision-resistant title based on the source scene title plus `(part 2)`, `(part 3)`, etc., and starts with blank editorial-only production notes. The original scene retains its notes. The editor disallows first-line splits (which would create an empty scene), prevents scene splits during active jobs, and refuses a 201st scene, ambiguous existing scene/line identifiers or malformed generated IDs. The pure helper also checks source and line uniqueness independently of the UI. Tested in no-model TypeScript and mocked-Tauri React flows, not with genuine Hindi narration or a clean Windows machine.

## Scene templates by safe duplication

Long scene names now truncate on complete Unicode code-point boundaries when generating bounded copied titles, avoiding malformed surrogate pairs in emoji/mixed-script scene titles. The original source scene title remains untouched; no scene is rendered or saved automatically.

Creators can use **Duplicate scene (fresh audio)** on the active scene. The copy is inserted immediately after the original and selected for editing. Its reviewed Hindi text, stage directions and assigned speakers are retained, but its scene and line IDs are regenerated; copied lines are explicitly reset to **pending**, with no old audio reference or duration. Existing work stays untouched. The title becomes `(copy)`, `(copy 2)`, etc. (bounded to 120 characters).

The operation refuses a missing scene, an ID collision, a project already at 200 scenes, or duplication that would push the full-story speech total above the current 256-cue render/SRT limit. It does not clone model output or certify duplicate speech: a new render and human listening review are required. The source script and glossary stay unchanged and nothing is written until the user saves.

## Reliable deferred editor events

The desktop now captures the chosen speaker, destination scene, character name, and voice-slider numeric values **before** scheduling the React document update. This prevents delayed updates from reading a reset control value and accidentally applying an empty or old selection. Manual assignment and cross-scene line moves are checked with deferred React state-updater tests. The editor does not automatically infer voices or regenerate synthesis because a select changed.

## Live unresolved-speaker feedback

The unknown-speaker alert now reads unresolved speech lines from the **current scene document**, rather than retaining a one-time parser warning after the author manually reassigns a character. Resolving the final unknown speaker clears the alert, and switching to another story cannot leave the previous story's unknown labels displayed. This is a UI state correction, not inferred speaker identification or automatic voice conditioning. A mocked desktop test confirms manual speaker assignment and the cleared warning.

## Production notes and safe scene removal

- The selected scene has an editable **Production notes for this scene (not spoken)** field. Notes may contain newlines, are limited to 4000 characters (the native project storage limit), and reject nonprinting control characters. They remain attached to the saved scene, separate from the original script and spoken text; they are not read aloud.
- **Delete scene (keep original script)** shows an explicit confirmation before removing that scene from the edited v2 project. It leaves the original source script, other scenes, pronunciation glossary and characters unchanged; the result is unsaved until the user chooses Save.
- After deletion, selection moves to the next scene where possible, then the preceding scene, or an empty state if none remain. Editing or deleting a scene invalidates stale preview/review state through the existing mutation handler.
- Missing or duplicated scene IDs fail closed. Tests exercise multiline Hindi notes, invalid values, cancellation and deletion without a speech model. The user should save a backup before making large narrative changes; there is no automatic undo of a saved deletion.

## Character cloning safety and native save compatibility

The **Duplicate voice profile** action now checks the native 100-character cap, requires unique and valid character IDs, rejects ambiguous duplicate source IDs, and generates unique copied names within the native 120-character title/name limit. Long Hindi character names are trimmed at Unicode code-point boundaries when adding a `copy` suffix. The desktop disables Add and Duplicate controls when already at capacity and during active rendering. Copying a profile carries voice parameter *settings*, not an experimentally verified distinct speaker identity. Model-free tests cover ID collisions, caps, Unicode names and disabled controls.

## Scene identity integrity

Cross-scene moves now reject nonunique destination scene IDs instead of silently inserting a dialogue line twice. In-scene reordering also rejects an ambiguous source scene ID before editing. Freshly duplicated scene/segment identifiers are checked for emptiness, length (maximum 80 characters), control characters and collisions before accepting the copy. These checks protect save and render compatibility with the Python v2 contract; they do not repair pre-existing corrupted documents.

## Corrupt-document and no-op edit safeguards

Additional model-free safeguards prevent older editor operations from silently editing multiple records if a loaded file contains duplicate scene, cast or dialogue IDs. Scene reorder/rename, character rename/deletion, speaker assignment and reviewed-speech correction now require one exact intended target. A move-to-current-scene or unchanged reviewed voice/text does not modify the document or clear the line's cached metadata. Moving a line to a different scene retains the same line object and appends it once. Invalid/missing identifiers fail with explicit errors rather than reporting a successful edit.

The React studio disables ↑/↓ scene reordering at the boundaries and locks character names, sliders, deletion, scene titles, speaker assignment and cross-scene moves during a pending script parse or narration render. New mocked IPC tests exercise disabled controls and boundary behavior, while TypeScript unit tests check duplicate-ID documents and no-op stability. Normal rendering/recovery behavior remains unchanged; there is still no tested clean Windows or genuine Hindi model acceptance.

## Test plan

The unit tests cover safe duplication limits, title conflicts, fresh IDs and audio resets, and narration–direction swaps, preservation of actor and cache fields, immutable input documents, edge no-ops, and missing/duplicate IDs. The mocked-Tauri React integration tests check duplicate-scene behavior and accessible buttons, disabled boundaries, output line order, unsaved state, and the absence of accidental synthesis.

Manual QA (not yet performed): With the local source build, parse the [Hindi dialogue test fixture](../qa/hindi-manual-listening-fixture.md), reorder a spoken line and a bracketed stage direction, save and reload, inspect scene preflight, and then compare new audio against the intentionally revised scene ordering. Real Hindi quality and clean-Windows tests remain tracked in [issue #3](https://github.com/sanskarIN/KathaSvara/issues/3).
