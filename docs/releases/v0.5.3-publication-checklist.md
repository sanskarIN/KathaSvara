# KathaSvara v0.5.3 — experimental prerelease operator checklist (DRAFT)

**NOT PUBLISHED.** This checklist prepares an unsigned, unbundled Windows developer prerelease **after** v0.5.2 is published. This document is not approval to merge unfinished v0.5.3 work, tag a build, or skip Hindi human acceptance for a stable product.

## Gate 0: Publish v0.5.2 before advancing main

- [ ] An authorized maintainer has dispatched the [exact-SHA v0.5.2 manual workflow](https://github.com/sanskarIN/KathaSvara/actions/workflows/release-v0.5.2.yml) from `main` with the approved full commit SHA.
- [ ] [v0.5.2](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.5.2) exists with **prerelease=true**, its original immutable commit, and exactly `KathaSvara-v0.5.2-dev-win64.exe`, `README.txt`, `SHA256SUMS.txt`.
- [ ] The older tag and published workflow remain unchanged. Do not update public website 'latest' claims until the release actually exists.

Until these are true, **do not merge the v0.5.3 development stack into `main`** and **do not run v0.5.3 release dispatch**.

## Gate 1: Freeze and verify the complete v0.5.3 code

- [ ] Integrate the v0.5.3 development PR stack in dependency order and review code, documentation and any new Windows helper options.
- [ ] Update **all** version fields to `0.5.3` together: desktop `package.json`, its npm lockfile root and package entry, `tauri.conf.json`, Rust `Cargo.toml` and `Cargo.lock` if version metadata requires it, and Python `pyproject.toml`.
- [ ] Update `.github/workflows/windows-portable-candidate.yml` only for the new *development candidate* artifact label; preserve release history and tagged workflow behavior.
- [ ] Review draft [v0.5.3 release notes](v0.5.3-notes.md) and [version-specific README](../installation/portable-windows-v0.5.3.md). They must honestly disclose the unsigned EXE, Python/model requirements and unverified real Hindi/Windows acceptance.
- [ ] At a final chosen `main` commit, verify Python Ruff/tests, React tests/build, Windows Rust tests/Clippy, Windows Python journal tests and the unsigned EXE build all succeeded for **that exact SHA**.
- [ ] Confirm `v0.5.3` tag and release do not exist. Never overwrite an old tag or upload replacement release attachments.

## Gate 2: Authenticated manual release dispatch

- [ ] Open [Actions: Publish KathaSvara v0.5.3](https://github.com/sanskarIN/KathaSvara/actions/workflows/release-v0.5.3.yml).
- [ ] Use branch **main** and the **full 40-character SHA of its current tip** in `release_sha`; do not use a PR merge ref or obsolete commit.
- [ ] Check `prepare`, `python`, `frontend`, `rust-windows`, `windows-python-lock`, `windows-exe`, then `publish`. A failed/skipped/cancelled job is not an approved release.
- [ ] The publishing job independently rechecks v0.5.2 as an existing prerelease, that `main` still equals the tested SHA, that components identify `0.5.3`, and that the tag is unused.
- [ ] If no authenticated workflow dispatcher is available, stop here; keep the draft, branch and tag untouched rather than weakening any safeguards.

## Gate 3: Verify the actual published prerelease

- [ ] The [v0.5.3 release](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.5.3) is marked **Pre-release**, not stable, and the tag resolves exactly to the dispatched SHA.
- [ ] It has exactly three assets: `KathaSvara-v0.5.3-dev-win64.exe`, `README.txt`, `SHA256SUMS.txt`.
- [ ] `README.txt` contains `NOT A COMPLETE INSTALLER`, `Python 3.11`, and honest model/weight disclosures.
- [ ] Verify the downloaded EXE's checksum using `SHA256SUMS.txt` and record results.
- [ ] Only **after** publication, update the public website/version links and archived workflow policy tests to the truly published version.

## Independent human audio/Windows acceptance

Keep [issue #3](https://github.com/sanskarIN/KathaSvara/issues/3) open until genuine Hindi speech, actual exported WAV/SRT, distinct voice capabilities and clean Windows behavior have been tested. Automated tests, file structure checks, fake model fixtures and EXE compilation do not count as human acceptance.

This checklist authorizes **preparation**, not early release, automated model downloads, stable branding, or retroactive claims about older executables.
