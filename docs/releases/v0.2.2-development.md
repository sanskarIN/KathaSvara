# KathaSvara v0.2.2 development — cache safety and recovery

**Status:** first cache batch merged as [PR #7](https://github.com/sanskarIN/KathaSvara/pull/7); streaming and render-journal changes are under development on `dev/v0.2.2-streaming-render-journals`. This is **not** a GitHub release. The latest verified public experimental pre-release remains [v0.2.1](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.2.1).

## First development batch: inspect before deleting

- Project-scoped source audio is cached as 64-character lowercase SHA-256 filenames ending in `.wav` under the dedicated `segment-cache` application directory.
- A new local Python `cache_stats` action inspects cache bytes, file counts and ignored unrelated entries without loading any speech model or writing to the filesystem.
- A `cache_prune` action defaults to **dry-run** and accepts a byte budget. The desktop accepts 16–2048 MiB; Settings currently offers a 512 MiB conservative maintenance target.
- Files younger than **10 minutes** are protected from eviction, including files a render may have just written.
- Only direct, regular, correctly named cache WAV files are candidates. The cache root itself cannot be a symlink; unrelated files, subdirectories, links, project JSON, exported WAV and audio previews are excluded.
- Entries are checked again by device, inode, length and nanosecond modification time immediately before deletion. Deleted entries can be generated again from the saved story; editing content always changes the cache fingerprint.
- Settings requires a **preview followed by explicit confirmation** before removal. The cleanup action reevaluates the actual cache at the time it runs, so reclaimed bytes may differ from a previous preview.

## Second development batch: streamed WAV and recovery journals

- Replace the previous full-story `numpy.concatenate(combined_parts)` operation with incremental mono PCM16 WAV composition in the destination directory. Only the current dialogue segment needs to remain in memory for the final mix; segment synthesis itself still buffers chunks.
- Enforce the 20-minute frame bound while writing. On failure or cooperative cancellation, discard the temporary combined WAV rather than exposing a partial final output.
- Finalize the WAV header and atomically publish using a same-directory hard link, refusing to overwrite a destination created during rendering. Hard-link support in the destination filesystem is required; publication fails safely if unavailable.
- Write optional atomic JSON render journals scoped to individual UUID job IDs under app data `jobs/`. Journals record a version, story ID, completion counts, segment IDs, content cache keys, cache reuse flags, measured durations and terminal state (`completed`, `failed`, `cancelled`). **They never store the story text, synthesized audio, private local file paths or model weights.**
- Keep a `running` state if the worker or operating system stops without a chance to finalize the journal. The studio now shows the 10 newest stored job reports for the selected story, labeling persistent `running` entries as potentially interrupted.
- Explicit retries generate a fresh UUID and automatically reuse valid existing content-addressed cached segments where voice inputs are unchanged. No automatic resume/restart is claimed.
- Model-free fake-engine tests verify successful duration, failure, cancellation, cleanup, no-overwrite behavior and retry reuse.

The desktop preview remains capped at **25 MiB** and is still loaded into memory for base64 transport to React. The streaming change improves the compositor memory profile but does **not** enable arbitrary-length previews or solve model-level memory limits.

## Limitations and safety

There is currently no durable cross-process active-render lock; the grace period reduces the risk of deleting recently written entries but does not prove a file is unused. Never schedule cleanup automatically during inference. The CLI is intended for KathaSvara's own dedicated cache, not arbitrary filesystem cleanup. Older cached audio may be re-synthesized if removed.

Cache cleanup and model-free unit tests do not demonstrate a working Chatterbox installation, a verified distinct actor voice or successful Hindi audio listening. These still require manual acceptance under [issue #3](https://github.com/sanskarIN/KathaSvara/issues/3).

## Validation criteria before integration

```sh
cd services/inference
python -m ruff check .
python -m pytest -q

cd ../../apps/desktop
npm ci
npm run test
npm run build

cd src-tauri
cargo fmt -- --check
cargo test
cargo clippy --all-targets -- -D warnings
```

CI should run this full matrix on the development pull request. Remaining v0.2.2 work: review code/CI feedback, cross-process cache locks, stale-journal retention and cleanup, clearer native GUI cancellation, and manual real-model acceptance. Do not publish a release or promise standalone Windows packaging on the basis of this batch.
