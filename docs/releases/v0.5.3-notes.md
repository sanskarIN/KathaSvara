# KathaSvara v0.5.3 — Experimental Hindi Audio Recovery & Scene Workflow Developer Preview

> **DRAFT — NOT PUBLISHED / NOT STABLE.** This file is release preparation, not evidence of a tag, a release, an executable artifact, working Hindi model inference, or a successful clean-Windows launch. **Do not publish before the separately guarded v0.5.2 prerelease exists and the v0.5.3 exact-commit build and tests pass.**

**कथास्वर — Give Every Story a Voice.**

## Changes planned since v0.5.2

- **Opt-in longer audio jobs:** the native desktop bridge preserves the 10-minute default timeout, with an explicitly bounded 10–120-minute override for speech synthesis and long-story composition (Windows helper `-RenderTimeoutMinutes`). Health checks, no-model import probes, and WAV inspections keep independent short budgets. Rust unit tests verify boundary and invalid values; no faster or successful CPU rendering is claimed.
- **Speech startup recovery:** the opt-in `KATHASVARA_TTS_DEVICE=cpu` setting bypasses failing CUDA/MPS capability probes, while `auto` retains the ordinary GPU-first device selection. The Windows source helper supports `-CpuOnly`. CPU mode needs a compatible Python/PyTorch installation and approved model weights; no performance or audible-output guarantee is made.
- **Conservative optional-API proof:** Python `**kwargs` adapters can syntactically accept experimental parameters without forwarding them to the speech model. V3/reference preflight therefore marks generic wrappers as **unverifiable** rather than falsely reporting compatibility, while keeping the default V2 path unchanged. Model-free tests cover backend and React diagnostics; no audible Hindi guarantee is implied.
- **Earlier detection of incompatible Chatterbox installations:** the no-model TTS preflight now checks the installed API signatures before accepting experimental V3 selection (`t3_model`) or a local reference WAV (`audio_prompt_path`). The Windows DoctorOnly helper and desktop Settings show a specific incompatible/unknown status without loading weights or leaking private filenames. The default V2/no-reference path remains compatible with older versions. A passing signature check is not evidence of checkpoint availability or audible Hindi.
- **Generated-audio signal safety:** a nonzero DC-only waveform previously passed the generated PCM16 raw-RMS test despite containing no changing signal. Both single narration and scene/story renders now require a centered RMS above one PCM16 step; cached segments with DC-only content are rejected and regenerated. Mock-engine transport fixtures use numerical varying samples. This is not a guarantee of intelligible Hindi speech and cannot replace human listening.
- **Stereo reference correctness:** the PCM16 signal inspector now measures time variation separately in the left and right channels, rejecting fixed opposite-channel DC offsets and anti-phase waveforms that would disappear when Chatterbox downmixes audio to mono. This does not verify human speech, speaker ownership or audio quality.
- **Reference recording signal checks:** local voice-reference WAV validation now rejects constant DC offsets even when the raw signal amplitude is high. A mean-adjusted PCM variation test complements the existing silence and single-spike safeguards. Test fixtures use synthetic varying PCM; no human voice or Hindi intelligibility is inferred.
- **Reference integrity during model startup:** a selected local voice recording is checked again immediately before and after its first use by Chatterbox. If the file was replaced while the model loaded or conditioned the first chunk, the job now stops with a fixed privacy-safe error instead of caching audio under a stale voice-reference SHA-256. This is a consistency safeguard, not voice identity or Hindi listening verification.
- **Voice-reference disclosure in generation screens:** both Voice Studio and Characters & Scenes display the active session mode before generation without exposing the selected private WAV path. Scene controls explicitly warn that one reference applies to all characters and distinct voice identities have not been verified. React tests cover session selection, clearing and privacy.
- **Voice-reference session race safety:** an older native WAV-picker result cannot reinstate a reference after Clear, and an in-progress, model-free Chatterbox preflight cannot publish a result for a recording that has since changed. In-flight narration from the previous voice is retired and its preview discarded without overwriting the new selection's status. React regression tests cover delayed dialog and probe completions; no model weights or private paths are required.
- **Local reference chooser in the desktop app:** Settings can now select a user-owned or consented WAV for the active session. The path remains in frontend memory only and is provided as a process-scoped environment override to the Python child for model-free preflight, short narration generation, and story dialogue renders. Native validation rejects non-WAV, relative, missing or symlink paths before starting that subprocess; Python checks actual PCM and speaker conditioning. The selected path is not saved to stories or localStorage, shown in diagnostics, or sent to external services. Clearing the selection returns to the launcher's default. One reference is used per render, not individual character voices. Real Hindi and clean Windows playback still require manual acceptance.
- **Optional local reference-voice conditioning:** the Windows helper accepts an explicit `-ReferenceWavPath` for a user-owned or consented 16-bit PCM WAV. A missing optional bundled speaker conditional now raises a fixed, actionable diagnostic instead of letting generation fail obscurely. Validation requires a local 2–20-second WAV; the preflight reports only valid/invalid status and does not load the model. Chatterbox receives the selected local file for on-device conditioning on the first generation; later chunks reuse conditionals. Voice reference content hashes separate cached output without publishing private paths. This is **one voice reference per inference process**, not verified multi-character voice casting, and does not certify natural Hindi output.
- **Experimental multilingual V3 checkpoint option:** `KATHASVARA_TTS_MODEL=v3` (or Windows `-ModelV3`) explicitly requests upstream Chatterbox Multilingual V3. Existing installations default to V2 with the legacy API call; no migration or weight download occurs from a no-model preflight. Model selection is validated without reflecting private environment values, the UI shows the chosen checkpoint, and voice-segment cache keys separate V3 from V2 without invalidating existing V2 cache entries. A compatible upstream Chatterbox version and V3 weights are still required; neither mock CI nor preflight is evidence of audible, intelligible Hindi or distinct speakers.
- **Safer native dependency failures:** Python, Torch, SoundFile and Chatterbox startup failures are converted to privacy-safe diagnostic hints. Raw OS exception text, private paths and tokens are not intentionally forwarded through the desktop JSON bridge.
- **WAV validation, not fake voice acceptance:** model-free tests reject empty, nonfinite, implausibly loud and effectively silent speech chunks. Both single narration and scene renders now check global PCM RMS, rather than peak alone, so a mostly silent waveform with one narrow spike is rejected before export or caching; existing silent cached chunks are regenerated. The separately opt-in `scripts/smoke_hindi.py` checks the real-model WAV's PCM16 structure, sample rate, duration and near-silent level, and streams its SHA-256 without reading the entire WAV into RAM. It does **not** listen or verify Hindi pronunciation.
- **Incomplete audio cleanup:** if a native WAV library fails after creating a temporary output or throws while closing a partial file, the streaming writer now attempts immediate cleanup instead of stranding an invalid file. Model-free failure-injection tests exercise both paths. Exclusive-create collisions with another process are now explicitly preserved instead of deleting the pre-existing temporary file (including symlinks); synthetic race and collision tests protect the no-overwrite contract.
- **Reliable dialogue composition:** zero-millisecond speaker pauses do not attempt empty writes; inter-speaker pauses and incremental chunk lengths are included in the 20-minute PCM frame budget *before* expensive audio concatenation. Valid short/zero pauses and over-budget handling have regression coverage.
- **Caching and recovery:** corrupt or effectively silent cached segments are rejected and can be regenerated. Cache WAVs now use exclusive staging-file creation; a preexisting or racing temporary path is preserved rather than truncated, and newly written cache headers are validated as mono PCM16. Forced regeneration may still refresh the final content-addressed cache entry. Synthetic filesystem regressions cover both collision safety and valid cache refresh. Cache reuse does not establish that the generated voice sounds natural or that separate characters have distinct voice identities.
- **Scene and character editing:** the v0.5.3 development branch includes deterministic dialogue-line ordering and source-preserving scene/character editor safeguards. Stage directions are not synthesized as speech. Source-only and mocked desktop tests check selection, edits and document integrity, but not genuine Windows interaction or narration.

## Developer EXE and companion assets — only after publication

The guarded v0.5.3 publication workflow is designed to produce exactly three assets:

1. `KathaSvara-v0.5.3-dev-win64.exe` — **unsigned, unbundled Windows x64 developer executable**, not a setup installer.
2. `README.txt` — version-specific runtime/setup prerequisites and trust limitations.
3. `SHA256SUMS.txt` — SHA-256 checksum matching the exact released EXE.

**No v0.5.3 binary exists just because this draft file or workflow exists.** Any CI-generated candidate is a temporary developer test artifact, not a published release asset. After publication, verify all three uploaded assets, the prerelease flag, exact immutable tag/commit and the downloaded checksum.

## Real local inference is separately configured

The developer EXE does **not** bundle Python 3.11, Chatterbox, PyTorch, third-party voice models, checkpoints, a compatible GPU driver, a voice catalog, or a managed installer. Use an authorized model/weights revision and a configured local Python environment; consult [audio troubleshooting](../installation/audio-troubleshooting.md) and [the Windows developer setup](../installation/development.md). Real model downloads are opt-in and subject to upstream terms.

The actual purpose of the generator is **audible Hindi narrated WAV speech**, followed by reviewed scene dialogue, manual speaker attribution and subtitle export. Compilation, import probes, synthetic PCM tests, and structural WAV inspection are not proof of that goal.

## Remaining acceptance gates

- **Real Hindi quality:** human listening to a genuine licensed Chatterbox run, including pronunciation, mixed Hindi/English words, long-form passages, silence/clipping, and narrator–character turns.
- **Distinct voices:** multiple cast names and adjustable parameters do not establish unique, independently conditioned voice identities. Do not advertise verified multi-voice output.
- **Clean Windows acceptance:** test actual launch, source/Python configuration, audio preview, save/reload, cancellation, cache, SRT and WAV export, and trust prompts on a clean supported machine.
- **Release ordering:** publish/verify experimental v0.5.2 first; merge and revalidate the complete v0.5.3 development work only after the protected v0.5.2 exact-SHA workflow has finished. Run v0.5.3 publication from its **final tested main SHA** through the separately gated manual workflow. Never rewrite an older tag or change the historic v0.5.2 workflow.
