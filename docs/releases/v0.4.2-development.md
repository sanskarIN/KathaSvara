# KathaSvara v0.4.2 — Model-free story render preflight (development)

**Status:** development only. Not tagged or published; [v0.4.1 is now published as an experimental pre-release](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.4.1).

## First development batch

- Add a lightweight preflight action that verifies scene and dialogue selection, assigned speakers, supported voice settings, and bounds for spoken segments, characters and engine chunks **without downloading weights, loading a TTS model, writing WAVs or starting a render job**.
- Count actual planned chunks after the project's pronunciation glossary is applied. Return only aggregate counts, not script text, speaker quotations or a fabricated duration estimate.
- Show an **Inspect render plan (no model)** button in Characters & Scenes. Invalid selections surface errors before users commit to a long voice-render job.
- Unit tests cover full and single-line rendering plans, invalid filters, unknown speakers and privacy-safe report fields.
- These checks cannot predict actual inference seconds, audio size, quality, pronunciation, model compatibility or distinct character voices. Results are advisory until real synthesis is tested.

## Shared, immutable-in-memory render plan

- Consolidate selection rules, speaker assignment validation, glossary substitutions and dialogue chunk splitting in a single **model-free `prepare_render_plan`** function. The public `inspect_render_plan` API returns counts only; it never transmits prepared text or model/cache identifiers.
- The actual renderer consumes that same prepared speech/chunk snapshot. This prevents a second independent normalization pass during synthesis and keeps subtitle text and cache fingerprints consistent with the checked script.
- Plan storage is strictly transient in the Python worker; nothing new is persisted to the story, progress journal or cache solely because someone inspects a plan. The renderer still creates audio and journals only when explicitly invoked.
- New regression tests verify glossary-adjusted Hindi speech, one normalization per selected line, selected-line isolation, unchanged input story objects and private aggregate reports. Existing audio cache and safety checks remain in force.
- These are deterministic no-model tests, **not** evidence of natural Hindi delivery, successful actual Chatterbox inference or clean Windows app acceptance.

## Planned follow-up

- Validate model/audio runtime and Windows app behavior manually, then add more integration regression cases for script editing during an active inference job.
- Test more complex Hindi glossary expansion and chunk-limit boundary cases.
- Build and manually verify Windows app controls, real-model Hindi listening and clean-device runtime setup before any new release.
