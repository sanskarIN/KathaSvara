# KathaSvara v0.5.0 — Experimental Hindi Production QA Developer Pre-release

**कथास्वर · Give Every Story a Voice.**

> **PRE-RELEASE / NOT STABLE.** KathaSvara v0.5.0 is an experimental developer build. The attached Windows EXE is **unsigned and unbundled**; it is not an MSI/NSIS installer, does not contain Python, Chatterbox, GPU dependencies, model checkpoints or voices, and has **not** passed manual natural-Hindi-listening or clean-Windows-machine acceptance. Do not bypass operating-system security protections to run an untrusted binary.

## New since [v0.4.2](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.4.2)

- **Scene-by-scene render readiness audit:** inspect model-free readiness for each Hindi story scene and for the combined production. The app checks assigned speakers and script/segment/chunk limits without claiming model or sound quality verification. Structural audit reports use fixed reason codes.
- **Privacy-safe audit JSON export:** optional, explicit export of aggregate counts, numbered scene statuses and fixed reason codes—without script text, scene/story IDs, character names, private voice settings, recordings, or model paths. Native validation rejects unknown/forged fields and existing destination files; sharing even structural counts remains the user's choice.
- **Manual retry of incomplete render attempts:** failed, cancelled and interrupted journal entries now offer an explicit confirmation before a **new full-story job**. It uses the **current** story and settings, may reuse unchanged cached speech, and does **not** reconstruct the original scene/line scope or automatically resume.
- **Nonpersistent per-WAV human QA checklist:** listen to the current WAV, inspect Hindi pronunciations, check character turns and review dialogue SRT. SRT must first be exported before its review checkbox can be marked. No automatic audio acceptance is inferred; changing audio or script resets the checklist.
- **Matching Hindi-friendly WAV and SRT filenames:** suggested export names capture the full-story, selected-scene or selected-dialogue scope at render time, using safe Unicode filename components and scene numbers. Editing the story or replacing audio during an open export dialog invalidates the old export.
- **Desktop interaction regressions:** five new React component interaction cases run against a mocked Tauri bridge for audit/export, selected-scene render, review gating, stale dialog and manual retry. They test software behavior, **not** actual Chatterbox synthesis or Windows WebView2 launch.
- **Read-only offline WAV inspection** in the Python source: `python -m kathasvara.wav_acceptance --wav <absolute-file.wav>` checks mono PCM16 file structure, bounded frame count/duration, SHA-256 and conservative streaming peak/RMS dBFS and clipped-sample indicators. Near-silence (RMS at/below -60 dBFS) and suspected clipping (at least 1% full-scale PCM samples) are **advisory warnings only**. The inspector never certifies pronunciation, voice identity, naturalness, emotions, or subtitle sync.
- **QA procedures and release transparency:** Windows 11/Chatterbox manual acceptance checklist and clear separation between simulated tests, structural audio validation and human listening.

## Downloads and integrity

The gated release workflow uploads **three files** only after the full exact-commit build/test and post-upload checksum verification succeed:

1. `KathaSvara-v0.5.0-dev-win64.exe` — unsigned Windows x64 **developer executable only**, NOT a self-contained installer.
2. `README.txt` — dependency setup, verified scope and security limitations. **Read before attempting to run**.
3. `SHA256SUMS.txt` — SHA-256 checksum of the uploaded EXE.

Verify the EXE digest from `SHA256SUMS.txt` using `Get-FileHash -Algorithm SHA256` in PowerShell. If a required asset or checksum is missing or does not match, treat the release as incomplete. Windows WebView2 prerequisites and a compatible local runtime are needed.

## Python 3.11 and Chatterbox are NOT bundled

For real speech, separately install and configure **Python 3.11**, KathaSvara inference sources, compatible `chatterbox-tts` / PyTorch audio dependencies and any properly licensed, locally approved weights. Point `KATHASVARA_PYTHON` and `KATHASVARA_INFERENCE_DIR` to appropriate **absolute** local paths. The model-free audit, UI tests and WAV inspector do not download model weights or establish GPU compatibility. See [Windows developer setup](https://github.com/sanskarIN/KathaSvara/blob/main/docs/installation/portable-windows-candidate.md) and [manual Hindi/Windows acceptance](https://github.com/sanskarIN/KathaSvara/blob/main/docs/qa/windows-hindi-acceptance.md).

## Known limitations — still NOT VERIFIED

- Real Chatterbox Hindi clarity, pronunciation and naturalness, including mixed-script speech and long stories, require human listening on authorized hardware. Distinct character voices are **not verified** and cannot be promised merely because the UI supports character names.
- No clean Windows install/use acceptance, signed executable, bundled interpreter, MSI/NSIS installer, commercial licensing guarantee or included model weights. Windows SmartScreen may warn about unsigned binaries; **do not bypass protection to run untrusted downloads**.
- Long renders have established per-job text, 256 dialogue segments, 500 chunk and 20-minute caps; full WAV files above the inline preview limit should be exported and listened to in another player.
- Dialogue SRT cue timings come from measured rendered segment boundaries, **not** independent word-level transcription. Review both content and timing before publishing.
- Render cancellation is cooperative; caches and journals support retries of unchanged speech only under their documented validation rules. The user chooses a new full-story attempt.
- WAV integrity/level warnings can flag technical problems, **not** detect all silent intervals, natural speech, emotion, correctness, clipping, alignment or distinct actor voices. A warning-free report still requires listening.
- Frontend dependencies currently lack a committed npm lockfile; [issue #33](https://github.com/sanskarIN/KathaSvara/issues/33) tracks reproducible dependency installation and Dependabot compatibility.

**Manual model and clean-Windows acceptance remains open in [issue #3](https://github.com/sanskarIN/KathaSvara/issues/3).** This pre-release is for developer evaluation, **not** a stable application.
