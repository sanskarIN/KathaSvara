# KathaSvara v0.3.0 — Experimental Hindi Story Studio developer pre-release

**कथास्वर · Give Every Story a Voice.**

This is an **experimental, unsigned, developer-focused Windows x64 pre-release**. It is **not a stable release, not an installer, and not a self-contained Hindi speech engine**. It builds on the v0.2.1 developer preview and incorporates the independently tested v0.2.2 development batches from [PR #7](https://github.com/sanskarIN/KathaSvara/pull/7), [PR #8](https://github.com/sanskarIN/KathaSvara/pull/8), and [PR #9](https://github.com/sanskarIN/KathaSvara/pull/9).

## New in v0.3.0

- **Local segment cache controls:** inspect bytes and entry counts, preview a conservative 512 MiB budget cleanup, and confirm before deleting eligible older speech chunks. Newly written files receive a 10-minute grace period; unrelated files and symlinks are ignored.
- **Streaming multi-scene WAV composition:** write the combined mono PCM16 narration incrementally instead of concatenating every segment into one large in-memory story waveform. Enforce a 20-minute frame limit, discard incomplete temporary files after catchable errors, and publish a finished WAV without replacing an existing destination.
- **Local per-job recovery journals:** record UUID job ID, story ID, completion counters, cache keys, measured segment duration and completed/failed/cancelled state. Journal entries **do not include script text**, generated audio, or private absolute paths.
- **Interrupted render identification and manual retry:** the app distinguishes a job actively running in the current process from a stale `running` record left after a restart. Manually retry to reuse compatible cached speech. There is no automatic restart or guaranteed crash-safe resume.
- **Story-specific history and safe cleanup:** see the newest render attempts for a story and confirm removal of an individual inactive journal record, without deleting projects, cached speech or exported WAVs.
- **Cooperative cancellation reliability:** keep an early cancellation request if issued before the worker starts; reject stale job cancel requests.
- **Cache maintenance versus active synthesis:** in-process mutual exclusion prevents the desktop from starting a cache prune while it has active renders, or starting rendering while in-process cleanup is underway.
- **Python subprocess reliability:** bounded output collection continues draining oversized responses to avoid deadlocking local subprocess pipes.
- Expanded Python fake-model tests, React checks, and Windows native Rust tests/Clippy. An unsigned developer EXE is built only after exact-commit checks pass.

The earlier [v0.2.1](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.2.1) features remain: Hindi pronunciation glossary, original/reviewed/effective text comparison, selective line re-render and explicit speaker assignment. v0.2.2 was a **development milestone**, not a separate published release.

## Download and Windows setup

If GitHub Actions publishes this pre-release successfully, it will attach:

- `KathaSvara-v0.3.0-dev-win64.exe` — **unsigned, unbundled Windows x64 executable**.
- `README.txt` — prerequisite and security warnings.
- `SHA256SUMS.txt` — SHA-256 checksum for the executable.

Before opening the executable, read `README.txt` and verify the checksum. Do not disable security protection to bypass unsigned download warnings.

**You must configure separately:** a compatible Python **3.11** runtime, `KATHASVARA_PYTHON` pointing to that Python executable, `KATHASVARA_INFERENCE_DIR` pointing to the absolute `services/inference` source directory, supported Chatterbox Multilingual dependencies and appropriately licensed/model-approved weights. Windows WebView2/Tauri platform prerequisites and sufficient compute/memory/disk are required. Neither Python nor Chatterbox nor voice-model weights are bundled. See [developer setup](https://github.com/sanskarIN/KathaSvara/blob/main/docs/installation/development.md) and [Windows developer-EXE notice](https://github.com/sanskarIN/KathaSvara/blob/main/docs/installation/portable-windows-candidate.md).

## Limits and independently unverified functionality

- **Real Hindi narration quality/playback has NOT been manually accepted**, and separate identifiable actor voices/speaker conditioning have NOT been demonstrated. Cast assignments are role metadata and supported per-character controls, not proof of distinct voices.
- No production-ready MSI/NSIS installer, code signature, self-contained runtime, managed GPU setup or bundled voice weights.
- Maximum 256 spoken segments, 100,000 spoken characters, 500 model chunks, 20 minutes of combined WAV; **desktop preview remains limited to 25 MiB** and its final audio is still transported to the React UI as base64. Streaming helps composition memory but does not remove this preview constraint.
- Cancellation is cooperative **between model chunks**, not an immediate hard kill. Inference timeout and failures may leave an incomplete `running` manifest; this is shown as interrupted on later app sessions.
- Segment-cache exclusion exists only within **one application process**. No cross-process lock exists yet; users should not run competing app instances while cleaning caches.
- Passing simulated-engine unit tests and an unsigned Windows CI compile **do not verify a real model, clean Windows interactive launch or listening quality**. These remain outstanding in [acceptance issue #3](https://github.com/sanskarIN/KathaSvara/issues/3).
