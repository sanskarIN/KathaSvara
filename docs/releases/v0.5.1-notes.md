# KathaSvara v0.5.1 — Experimental Recovery & Cache Reliability Developer Pre-release

**कथास्वर · Give Every Story a Voice.**

> **PRE-RELEASE / NOT STABLE.** v0.5.1 is an experimental developer evaluation build, **not** a complete installer, validated Hindi narration product, or proof of clean-Windows functionality. Its Windows x64 EXE is **unsigned**, contains **no Python runtime, Chatterbox model, weights, checkpoints, GPUs or voices**, and has not undergone a human listening acceptance test. Do not bypass Windows security protections to execute an untrusted download.

## Improvements since [v0.5.0](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.5.0)

- **Safe recovery journal publication:** the very first JSON write uses an atomic no-overwrite publication so a colliding file or symlink from another process is not replaced; Windows model-free filesystem regressions verify this behavior.
- **Transactional journal progress:** subsequent progress updates build the next state before writing. A failed write restores the last recorded in-memory state. A normal exit with missing segments is marked `failed / IncompleteRender`, not falsely `completed`; extra segments beyond the plan are rejected.
- **Bounded recovery history:** directory listing scans no more than 20,000 entries, even when unrelated files are present. Individual manifest JSON reads are capped to 64 KiB and progress JSON to 1 KiB, including rechecking the opened handle and a capped stream read. Impossible completed counters and malformed records are rejected.
- **Safer desktop recovery UI:** pending history reads, forget acknowledgements and render-progress callbacks cannot repaint an obsolete project or job after a document switch, edit or new render. These are visual consistency safeguards, **not** automatic resumption of old speech.
- **Safer segment-cache maintenance:** scans include at most 20,000 files and reject incomplete inventories before any deletion. Invalid maintenance clocks cannot bypass the 10-minute protection for recently written files; only direct SHA-256-named regular WAVs are eligible and cooperating workers share an OS-managed lock.
- **Expanded regression coverage:** Linux Python test suite and Ruff, model-free native Windows Python journal tests, React/Vitest mocked desktop interaction tests, Windows Rust unit tests/Clippy, and Windows unsigned EXE candidate build. These checks are **not** speech-model, audio-quality, signed-installer or clean-machine acceptance.

## Download exactly these three release attachments

1. `KathaSvara-v0.5.1-dev-win64.exe` — unsigned Windows x64 **developer executable only**. It is **not** a standalone MSI/NSIS installer.
2. `README.txt` — runtime setup, trust limitations and prerequisites; read this before execution.
3. `SHA256SUMS.txt` — SHA-256 digest of the release executable.

Use `Get-FileHash -Algorithm SHA256` on Windows to compare the EXE digest with `SHA256SUMS.txt`. If any required attachment is missing or inconsistent, **do not trust the incomplete release**.

The guarded publication workflow builds the EXE on Windows at the exact release SHA, executes model-free tests, checks version synchronization and the bundle disclaimers, uploads the three companions, verifies their hashes, creates an immutable version tag as an experimental prerelease, then downloads the attachments again and rechecks the SHA-256 digest.

## Python/model dependencies remain separate

Install a compatible **Python 3.11** environment, the `services/inference` source project, approved `chatterbox-tts` / PyTorch dependencies, and the properly licensed, approved model weights yourself. Configure `KATHASVARA_PYTHON` and `KATHASVARA_INFERENCE_DIR` as absolute local paths. Models, GPU support and voice styles vary by setup; the developer EXE does not set these up automatically. Read the [Windows developer candidate instructions](https://github.com/sanskarIN/KathaSvara/blob/main/docs/installation/portable-windows-candidate.md).

The `Recent render history` UI offers an explicit **new full-story retry from the current document**; it does not restore the original partial job or the original scene-selection scope. Reusing unchanged valid cached speech is possible but does not prove quality. Source text and model paths are not persisted in recovery journals.

## Remaining acceptance blockers

- **Actual Hindi speech clarity, long-form pronunciation, emotion and supported character-voice differentiation:** unverified until listening to real Chatterbox audio on authorized hardware.
- **Windows application acceptance:** no verified fresh-user installation, UI interaction, signed build, packaged runtime or clean-machine speech-generation proof. Windows WebView2 and local Python may need setup.
- **Audio and captions:** WAV structural checks and signal-level warnings are advisory only; generated SRT timing is derived from measured speech-segment boundaries, not independent word alignment.
- **Operational scope:** generated output has per-job text, segment, chunk and 20-minute limits. Interrupted jobs require explicit retrials; safe filesystem behavior does not guarantee durability after power failure or protect against malicious writers ignoring app locks.
