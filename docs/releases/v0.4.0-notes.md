# KathaSvara v0.4.0 — Experimental production workflow pre-release

**कथास्वर · Give Every Story a Voice.**

This GitHub version is **an experimental open-source developer preview**, not a stable audio-production application. It extends the verified [v0.3.0 experimental pre-release](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.3.0), but does **not** claim separately verified Hindi narration quality, distinct performer voices or an independent Windows installer.

## What's new in v0.4.0

### Cross-process cache safety

- Add an operating-system-owned, nonblocking advisory lock shared by the Python story renderer and **destructive** speech-cache pruning. The sentinel remains in the app-data folder; it is **not deleted or recreated** between operations. The operating system releases its exclusive lock if an inference worker exits or crashes.
- Support Windows byte-range locking and POSIX flock via Python 3.11's standard library, with deterministic no-model interprocess and cancellation tests. A busy cache fails with a clear error, instead of silently deleting WAV segments while another participating worker synthesizes them.
- Continue the in-app Rust active-job exclusion added in v0.3.0. Cross-process locking only covers workers using the **same app-data cache directory and updated Python bridge**; independently run old builds, manually edited cache files and nonparticipating programs are outside the guarantee.
- Keep cache cleanup user-triggered, dry-run preview first, with ten-minute protection for recently modified cache WAV files. No automatic cleaning is enabled.

### Measured dialogue subtitles

- Add measured `start_seconds` and `end_seconds` offsets for **each generated dialogue segment**, derived from composed PCM frames including preceding pause offsets. There is no guessed reading-time formula.
- The Characters & Scenes studio can export **UTF-8 Hindi SubRip `.srt`** using the reviewed, readable dialogue text and the measured segment boundaries. Captions can be exported alongside the finished `.wav` preview after synthesis.
- Validate the cues against missing dialogue, overlap, invalid/non-finite timestamps, oversized captions and the 20-minute render cap. The native backend exclusively creates a **new .srt file** and refuses to overwrite an existing file.
- This is **line-level timing, not forced word alignment**. Narration speed inside each line, exact word timing, script pronunciation changes and punctuation are not automatically re-aligned. Listen and review before publishing subtitles on YouTube or another platform.

### Preserved features

- Offline-first Hindi script editor, explicit speaker assignment, project-local pronunciation rules, reviewed speech text and exact pre-TTS text preview.
- Local reusable SHA-256 segment cache, bounded user-confirmed cleanup, streamed combined PCM16 WAV, per-story progress/journals, interrupted-job display and manual cache-assisted retry.
- Single segment/scene/full-story rendering; correction and force retry; dark/light UI; local WAV export and no-model environment diagnostics.

## Windows developer EXE and integrity checks

When release CI succeeds, the GitHub pre-release attaches:
- `KathaSvara-v0.4.0-dev-win64.exe` — unsigned, **unbundled** Windows x64 developer executable, **not an MSI/NSIS installer**.
- `README.txt` — setup, dependencies and security disclaimer.
- `SHA256SUMS.txt` — SHA-256 digest for the executable.

The release workflow verifies exact `main` commit identity, refuses tag reuse, runs Python 3.11 tests and Ruff, React/Vitest TypeScript build, Windows Rust unit tests and Clippy, **Windows Python cross-process lock smoke tests**, and builds the unsigned EXE. It checks the SHA-256 before and after uploading to GitHub.

The EXE still requires Windows/Tauri WebView2 prerequisites, separately installed **Python 3.11**, supported Chatterbox Multilingual dependencies, appropriately licensed/approved model weights and adequate local resources. Set `KATHASVARA_PYTHON` and `KATHASVARA_INFERENCE_DIR` to absolute compatible paths. No model weights, managed Python, code signature or automatic update mechanism are bundled. See [Windows setup](https://github.com/sanskarIN/KathaSvara/blob/main/docs/installation/portable-windows-candidate.md) and [development instructions](https://github.com/sanskarIN/KathaSvara/blob/main/docs/installation/development.md).

Never disable Windows security protections simply to execute an unsigned download. Verify the EXE's SHA-256 using `Get-FileHash` before testing.

## Known limitations and unverified acceptance

- **No independently verified real Hindi audio listening**, no reproducible model/weights/hardware manifest, and no verified unique character voice identity. A mock-engine test is NOT evidence of narration audio quality.
- **No clean-machine interactive Windows startup, user-device export/playback or self-contained installer accepted.** These remain tracked in [issue #3](https://github.com/sanskarIN/KathaSvara/issues/3).
- At most 256 spoken lines and 100,000 spoken characters, 500 model chunks and 20 minutes combined WAV per render. Desktop audio preview remains limited to **25 MiB**, transmitted to React as base64.
- Cancellation is cooperative between model chunks, not instantaneous. A model fault or killed worker may leave a journal marked running until the next app session identifies it as interrupted.
- OS file locks coordinate only current, participating Python processes sharing the same cache folder. There is no cloud synchronization, cross-device lock, remote session management or guarantee against unrelated processes modifying files.
- SRT cue boundaries are based on segment PCM duration, not human-approved alignment or an independent ASR transcript. Stage directions are excluded.
