# KathaSvara v0.2.0 — Developer Implementation and Acceptance Tracker

> **Experimental developer pre-release candidate.** The maintainer has explicitly authorized publication of an early-access v0.2.0 source + unsigned EXE preview. This approval does **not** complete the manual audio and Windows acceptance gates below. GitHub Actions publishes only after complete automated validation; check the Releases page for actual publication.

## Core features implemented in the development branch

- Python schema v2 for characters, engine-specific voice profiles, scenes, spoken segments and stage directions.
- Explicitly labeled Hindi parser; supports lines like `राजा भोज: नमस्कार।`, `Narrator: ...`, Markdown `# दृश्य` headings and `---` scene breaks. Labels absent or ambiguous are not treated as automatically identified characters.
- Unresolved speaker labels remain unassigned and block rendering until manually corrected. Original text is retained separately from normalized spoken text.
- Schema migration from v0.1.x `{id,title,text}` retains original values. The Rust editor writes v2 files under a distinct app-data folder with atomic writes, rather than overwriting legacy projects.
- UI foundations for managing and duplicating characters, supported voice controls, creating/reordering scenes, moving dialogue, correcting speakers and saving/reloading v2 stories.
- Python multi-segment renderer: one model load per job, bounded chunking, per-segment reuse/cache, measured sample durations, pauses, click-reducing fades, scene selection, forced regeneration, atomic WAV creation and cooperative cancellation between chunks.
- React ↔ Tauri/Rust ↔ Python batch render IPC, progress-file reporting, 25 MB WAV preview limit, local export and UUID-scoped cancellation sentinel.
- Dedicated GitHub Actions workflow builds an *unsigned, unbundled* Windows EXE candidate, where CI allows. This is retained as a workflow artifact for inspection rather than automatically uploaded to a public pre-release.

## Model capability contract

- The current adapter calls `ChatterboxMultilingualTTS.generate(text, language_id="hi", exaggeration=..., cfg_weight=...)`.
- Multiple distinct voice identities, speaker references, emotion categories, pitch shifts or speed controls are **not** enabled in this release foundation. Cast assignments route the actual supported parameters but **must not be advertised as demonstrating distinct character voices**.
- The model revision and speaker-conditioning capabilities require further real-model evaluation; cached audio fingerprints include the profile's model ID, which should be revision-specific for reproducibility.

## Developer testing

```sh
cd services/inference
python -m pip install -e ".[test]"
python -m ruff check .
python -m pytest -q

cd ../../apps/desktop
npm install --no-audit --no-fund
npm run test
npm run build

cd src-tauri
cargo fmt -- --check
cargo test
cargo clippy --all-targets -- -D warnings
```

Runtime model weights and compatible hardware are needed for genuine speech testing. Tests using simulated audio validate transport/assembly only and MUST NOT be released as authentic Hindi narration.
