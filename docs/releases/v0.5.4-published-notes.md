# KathaSvara v0.5.4 — Experimental Audio Setup Doctor Developer Preview

**Experimental pre-release — NOT STABLE.** This release contains an **unsigned, unbundled** Windows x64 developer EXE and does not provide a complete installer or ready-to-run Hindi speech engine.

## What's new since v0.5.3

- **Actionable audio diagnostics:** the optional, model-free Python speech import probe identifies the first configuration blocker and recommends one fixed repair action, without printing private reference WAV paths or native binary error strings.
- **Better Windows first-time setup:** `-DoctorOnly` reaches the import probe when optional speech packages are absent, explains an **explicit opt-in** `-InstallDependencies` workflow, and does not load checkpoints, generate speech or automatically download package/model data.
- **Desktop Settings compatibility:** the next audio repair action is visible in Settings; an older local inference source that lacks the new field receives a safe setup message.
- **Tested safeguards:** deterministic Python tests, simulated React interactions, Windows Rust/Clippy and a developer EXE build can validate source behavior without proving sound quality.

## Included GitHub assets

- `KathaSvara-v0.5.4-dev-win64.exe` — **unsigned and unbundled** Windows x64 developer executable, **NOT A COMPLETE INSTALLER**.
- `README.txt` — setup and dependency disclosure.
- `SHA256SUMS.txt` — integrity hash for the executable.

The binary omits **Python 3.11, Chatterbox TTS, PyTorch, model checkpoints, and authorized weights**. External runtime setup is required. Do not disable operating system security protections to run an unsigned executable.

**What is not verified:** actual Hindi text-to-speech synthesis, intelligible Hindi pronunciation, naturalness, distinct speaker identities, consented reference-voice quality, and clean-Windows user acceptance. These remain open in [manual acceptance issue #3](https://github.com/sanskarIN/KathaSvara/issues/3). A model-free check, structurally valid WAV, or completed GitHub build does **not** establish listening quality.
