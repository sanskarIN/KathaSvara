# KathaSvara v0.4.1 — Experimental developer pre-release

**कथास्वर · Give Every Story a Voice.**

This is an **experimental, source-oriented Windows developer preview**, not a stable application or self-contained installer. It extends [v0.4.0](https://github.com/sanskarIN/KathaSvara/releases/tag/v0.4.0) with safer WAV export, subtitle validation, and explicit local recovery maintenance.

## Improvements

- Preserve successfully generated long mono PCM16 narration WAVs that exceed the **25 MiB inline-webview preview limit**. These can be exported to a new destination; playback inside the application remains unavailable above that limit.
- Stream WAV export rather than loading the whole recording into Rust memory. Validate WAV container structure, channel/rate, 20-minute duration, and 512 MiB bounds before export. Refuse destination overwrites.
- Align **dialogue-level** Hindi SRT text with the actual post-glossary spoken text submitted for synthesis. This is a text snapshot, not word-level forced alignment, audio transcription, or human-verified timing.
- Fix a native SRT newline parsing issue and reject invalid, overlapping, zero-length, out-of-order, or out-of-range captions using rounded millisecond timing.
- Handle corrupted or inconsistent post-render audio metadata without retaining an unaccepted final WAV.
- Add user-confirmed **24-hour-old abandoned partial WAV cleanup** in the dedicated audio and segment-cache folders. Preview first; no scheduled deletion. Preflight both directories, bound scan/deletions, reject symlinks, and reuse the cross-process cache lock.
- When a user confirms forgetting an inactive render history entry, remove only that job's validated cancellation/progress sidecar files alongside its journal; preserve original projects, final WAVs, speech cache and unrelated files.
- Reject scene/segment selection mismatches and impossible forced retries before model loading. Respect cancellation before heavy model setup, and check output sample budgets including inter-speaker pauses before caching newly generated audio.
- Expand model-free Python, TypeScript/React, and native Rust regression tests.

## Windows developer artifact

When the guarded publishing workflow succeeds, the release attaches:

1. `KathaSvara-v0.4.1-dev-win64.exe` — unsigned Windows x64 executable (not an installer, not self-contained).
2. `README.txt` — required runtime setup and security warnings.
3. `SHA256SUMS.txt` — SHA-256 digest for verifying the EXE.

The workflow checks the **exact main-branch SHA**, runs Python Ruff/pytest, React tests/build, Windows Rust tests/Clippy, Windows Python cache-lock tests, compiles the EXE, and verifies the checksum before and after upload. Tag reuse and overwriting a previous GitHub Release are prohibited.

**Runtime dependencies still external:** compatible Python 3.11, KathaSvara inference source, Chatterbox multilingual dependencies, separately licensed model weights, suitable local resources and WebView2/Tauri prerequisites. See [Windows setup](https://github.com/sanskarIN/KathaSvara/blob/main/docs/installation/portable-windows-candidate.md). Do not bypass Windows security protections to run an unverified unsigned executable.

## Still unverified — not stable

- No manually accepted real Chatterbox Hindi listening session, model/weights/hardware record, or verified distinct character voice output.
- No verified installation or interactive speech/render/export test on a clean Windows computer; no signed installer, bundled Python runtime, bundled model weights or auto-updater.
- Limits remain 256 spoken lines, 100,000 spoken characters, 500 chunks, 20 minutes of composed audio, and 25 MiB of inline WAV preview transport. Large files are export-only.
- Cooperative cancellation can only be observed between inference chunks, not within a model call. Recovery journals and manual retry are not crash-proof fully automatic resumable rendering.
- Cache locking covers participating workers only. Manual cleanup is bounded, explicit and can skip files changed after preview. SRT uses measured dialogue PCM boundaries, not verified word timestamps.

Track remaining acceptance in [issue #3](https://github.com/sanskarIN/KathaSvara/issues/3); do not describe a mock-engine test as proof of Hindi pronunciation quality.
